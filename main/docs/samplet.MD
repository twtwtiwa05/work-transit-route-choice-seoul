OTP(RAPTOR) 알고리즘과 교통카드 데이터 기반 경로 유사도 비교 방법
1. 연구 배경

공공교통의 경로 선택 연구에서는 예측된 최적 경로와 실제 이용자가 선택한 경로가 얼마나 일치하는지 분석하는 것이 중요하다. OpenTripPlanner(OTP)는 GTFS(공공교통 일정 정보)를 활용하여 RAPTOR(Round‑based Public Transit Optimized Router) 알고리즘으로 최단 이동시간 경로를 계산한다. 실제 이용자의 이동 경로는 자동 요금징수(AFC) 스마트카드 데이터를 통해 파악할 수 있다. 서울의 경우 하루 925만 건 이상의 스마트카드 데이터가 수집되고, 99%에 가까운 승객이 스마트카드를 이용한다. 최근 연구에서 RAPTOR 알고리즘으로 계산된 경로와 스마트카드 데이터에서 추정한 실제 경로를 비교한 결과, 환승이 없는 경우 약 84%, 환승 1회인 경우 약 88%에서 경로가 일치했으며 전체적으로는 약 70%의 일치율을 보였다. 경로 유사도를 평가하고 알고리즘을 개선하기 위해 구체적인 평가 지표가 필요하다.

2. 데이터 준비

RAPTOR 알고리즘 결과 추출

OTP에 서울시의 GTFS 데이터를 입력하고, 스마트카드 기록과 동일한 출발지‑도착지(O‑D)와 출발 시각을 이용해 RAPTOR 알고리즘으로 경로를 생성한다. 단일 경로뿐 아니라 K‑경로(예: 5개)도 계산해 다양한 대안을 확보할 수 있다.

일부 연구는 환승 페널티나 도보 속도 보정 등을 적용한 개선된 RAPTOR 알고리즘을 제안하며, 이 경우 알고리즘이 실제 승객 경로와 더 유사한 결과를 생성한다.

스마트카드 데이터 전처리

AFC 데이터는 승차·하차 정류장, 시간, 노선 번호, 카드 유형 등으로 구성된다. 지하철의 경우 중간 환승역을 알 수 없어 출발역과 도착역만 기록된다.

버스의 경우 승하차 정류장과 노선 번호를 통해 노선 순서를 파악할 수 있으므로 노선 ID와 정류장 순서를 이용해 경로를 재구성한다.

탑승 시간에 따라 출발 시각의 오차(±10분)를 고려해 여러 시간대의 알고리즘 경로를 비교하는 것이 바람직하다.

지도 연계 및 경로 시퀀스 생성

모든 경로는 정류장·역의 순서로 표현한 시퀀스로 변환한다. 버스와 지하철을 구분하여 기록하고, 환승 시에는 각 구간의 노선과 정류장 순서를 연속된 시퀀스로 이어준다.

3. 경로 유사도 지표

경로(정류장/역의 시퀀스)를 비교하는 방법으로 다음과 같은 지표가 사용된다.

3.1 정적 일치율(매칭 비율)

연구 사례에서는 알고리즘이 산출한 경로가 실제 승객 경로와 완전히 동일할 때 일치로 판단하여 전체 승객 대비 매칭률을 계산했다. 예를 들어 서울 사례에서 환승 1회인 경우 88%가 일치했다는 결과가 보고되었다. 이는 가장 간단한 유사도 지표이지만, 일부 노선이나 정류장이 일치하지 않더라도 부분적으로 유사한 경로를 평가하기에는 부족하다.

3.2 경로 중복률(경로 중첩률)

두 경로가 얼마나 많은 **공통 구간(정류장/노선)**을 공유하는지를 평가하는 방법이다. 공유된 정류장·노선의 비율이 높을수록 유사한 경로로 판단한다. 이는 **길이 기반의 중첩률(overlapping length)**에 해당한다. 다만 역·정류장의 순서와 선택 확률을 고려하지 않는다는 한계가 있다.

3.3 코사인 유사도(Cosine Similarity Index, CSI)

코사인 유사도는 두 링크 집합(알고리즘 경로와 실제 경로)을 벡터 공간 모델로 표현하여 각 링크가 선택될 확률(또는 빈도)을 요소로 하는 벡터를 만든다.

두 벡터의 코사인 값(CSI)이 1에 가까울수록 두 경로 집합의 선택 패턴이 유사하다고 판단한다.

실제 경로가 여러 개일 때(예: 여러 승객의 경로) 경로 집합 전체를 통계적으로 비교하는 데 유용하다.

3.4 Jaccard 지수 / Jaccard 유사도

경로를 정류장 집합으로 보고 두 경로의 교집합과 합집합의 비율로 유사도를 구한다. 보고서에서는 Jaccard 지수를 이용해 서로 다른 경로를 선택할 때 유사성을 평가하였다.

Jaccard 지수는 순서를 고려하지 않으며, 위치가 비슷하지만 다른 정류장으로 인식되는 경우에는 유사성이 낮게 나타난다.

3.5 LCS/LCSWT(최장 공통 부분수열 기반 유사도)

**Longest Common Subsequence (LCS)**는 두 시퀀스에서 공통으로 나타나는 가장 긴 부분수열의 길이를 구한다. 기본 LCS는 편집거리와 유사하며 노선과 정류장의 순서를 고려한다.

보고서에서는 LCS를 확장해 **LCSWT(Longest Common Subsequence with Transfer)**를 제안하였다. LCSWT는 정류장이 완전히 일치하지 않더라도 근접한 정류장을 부분적으로 매칭하여 공간적·시간적 근접성을 고려한다.

두 시퀀스 X, Y에 대해 L(X,Y) 를 얻은 후 길이 |X|, |Y|로 정규화하여 **대칭적인 불일치도 δ(X,Y) = 1 − 2 · [L(X,Y) / (|X|+|Y|)]**를 계산한다. 값이 0에 가까울수록 두 경로가 유사하다.

3.6 평균 경로 거리/시간 차이

경로 전체 이동 거리를 Haversine 거리 또는 GIS를 이용해 계산하여 예측 경로와 실제 경로의 거리 차이를 절대값 기준으로 비교한다.

각 구간의 실제 소요시간과 알고리즘이 예측한 소요시간을 비교하여 평균 절대 오차(MAE) 및 **평균 제곱근 오차(RMSE)**를 계산하는 방법도 있다. MDPI 연구에서는 예측된 승객 수를 검증할 때 MAE와 RMSE를 사용하였다; 이 방법을 경로 간 시간 차이 평가에도 응용할 수 있다.

3.7 동적 패널티 기반 유사도

환승시 페널티를 적용하면 알고리즘 경로와 실제 승객 경로의 유사도가 높아진다는 연구 결과가 있다. 개선된 RAPTOR 알고리즘은 환승 종류에 따라 페널티를 차등 적용하고 도보 속도를 보정한다. 실험 결과 단일 경로(K=1)의 유사도가 페널티 미적용 시 48.5%였던 반면, 페널티 적용 시 58.8%로 증가했다.

복수 경로(K=5)를 고려했을 때도 페널티 적용 시 유사도가 80.8%에서 91.4%로 증가하였다. 이는 알고리즘 경로를 수정할 때 통근자들의 환승 기피와 도보 선호를 고려해야 함을 보여준다.
