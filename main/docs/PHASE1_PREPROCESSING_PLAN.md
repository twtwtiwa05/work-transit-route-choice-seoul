## 핵심 발견: TCD 레코드 구조

TCD의 각 행은 **하나의 레그**(1회 탑승~하차)이다.

```
환승건수 = 해당 레그 시점의 누적 환승 횟수
  0 → 새로운 통행 체인의 첫 번째 레그
  1 → 1회 환승 후 탑승한 레그 (체인의 2번째 레그)
  2 → 2회 환승 후 탑승한 레그 (체인의 3번째 레그)
```

**실제 데이터 검증**:
```
카드 +++Fhrw9vzEc (5건):
  인련=1, 환승=0, BUS-105:  12:03~12:15  ← 체인A 시작
  인련=2, 환승=1, 지하철-201: 12:18~12:27  ← 체인A 2번째 (환승)
  인련=3, 환승=2, 지하철-201: 12:40~12:45  ← 체인A 3번째 (환승)
  인련=4, 환승=0, 지하철-201: 22:00~22:14  ← 체인B 시작 (새 통행)
  인련=5, 환승=1, BUS-105:  22:19~22:24  ← 체인B 2번째 (환승)
```

→ **체인 그룹핑: `환승건수=0`이면 새 체인 시작, `환승건수>0`이면 이전 체인 계속**

## 핵심 발견: 수단 분류 (ROUTE 마스터 교차검증)

**RESEARCH_PLAN.md의 수단 분류가 틀렸음 — 아래가 올바른 분류:**

```
교통수단코드 × ROUTE 교통수단유형 교차검증 결과:
  100~199: B (서울 시내버스)     → BUS
  200~289: T (도시철도)          → SUBWAY
  290:     G (기타)              → OTHER (제외)
  400~499: B (경기/인천 버스)    → BUS
  500~599: B (경기/인천 지방버스) → BUS  ← RAIL 아님!
```

- **500번대는 RAIL이 아니라 BUS** (ROUTE 마스터에서 전부 B로 확인)
- 코레일 수도권전철(경의중앙, 분당, 수인선)은 **코드 202로 SUBWAY에 이미 포함**
- 최종 수단은 **BUS / SUBWAY 2가지** (+ 극소수 OTHER 제외)

```python
def classify_mode(code):
    if 200 <= code <= 289: return 'SUBWAY'
    elif code == 290:      return 'OTHER'
    else:                  return 'BUS'
```

## Step 4: 정류장 시퀀스 추출 ✅

**파일**: `scripts/data/step4_stop_sequences.py`

### 목적

경로 유사도(S_jaccard, S_lcs 등) 계산을 위해, TCD 각 **버스 레그**가 실제로 경유한 정류장 목록 추출.

### 로직

ROUTESTTN에서 노선별 정류장 순서를 조회, 승차~하차 사이 구간을 추출:

```
ROUTESTTN에서 302번 버스 전체 시퀀스:
  [A, B, 강남역, 양재역, 매봉역, 도곡역, 수서역, C, D, E]

TCD 레그: 302번, 승차=강남역, 하차=수서역
  → 경유 정류장: [강남역, 양재역, 매봉역, 도곡역, 수서역]
```

순환노선 처리: 승차순서 > 하차순서인 경우 승차→끝 + 처음→하차 구간 결합

### 지하철 처리 전략

**지하철은 정류장 시퀀스 추출이 불필요하다:**

1. TCD 지하철 레그의 **하차정류장 ID가 승차정류장과 다른 체계** (탑승 노선이 아닌 하차 노선의 역 ID 사용)
   - 원인: 지하철 내부 환승은 카드를 다시 안 찍으므로, 2호선 탑승 → 4호선 하차 시 하차역이 4호선 역 ID
   - 2호선 승차 ID 50개 → ROUTESTTN 100% 일치, 하차 ID 752개 → 10% 일치

2. 지하철은 **"302번 vs 303번" 문제가 없음:**
   - 버스: 302번과 303번이 같은 정류장을 경유 → 정류장 비교 필수
   - 지하철: 2호선과 3호선은 경로가 완전히 다름 → **노선 매칭만으로 충분**

3. Phase 2 유사도 계산 시:
   - **버스 레그**: S_jaccard (경유 정류장 집합 비교)
   - **지하철 레그**: 동일 노선이면 1.0, 다른 노선이면 0.0 (노선 매칭)
   - **환승 구조/수단 구조**: S_xfer, S_mode로 별도 포착

### 실행 결과

```
총 레그: 18,106,743
  매칭 성공:      12,825,751 (70.8%)
  정류장 미매칭:   5,251,189 (29.0%) ← 97%가 지하철 (정상, 위 설명 참조)
  노선 미매칭:        29,803 (0.2%)

서울 시내버스 (100번대): 미매칭 0.0% ← 완벽

경유 정류장 수 (매칭 레그):
```

2. `trip_attributes.parquet` + OTP 결과 → **실제 통행 vs 대안 경로 매칭**
3. `leg_stop_sequences.parquet` → **5개 유사도 지표 계산**
   - 버스: S_jaccard (경유 정류장), S_lcs (최장 공통 부분시퀀스)
   - 지하철: 노선 매칭 (동일=1.0, 다름=0.0)
   - 공통: S_xfer (환승 구조), S_mode (수단 구조), S_combined (종합)
4. 선택 모형 추정 (Mixed Logit → Latent Class → LightGBM 벤치마크)
